# Project Context

## Цель

Персональная электронная библиотека (преимущественно художественная проза: фэнтези, LitRPG, научная фантастика) как первый полнофункциональный модуль личного макропортала.

Полные требования: `LIBRARY_PORTAL_MASTER_AGENT_PROMPT_RU.md` (§1–12).

## Пользователи

Один пользователь (владелец), многопользовательская модель заложена в схему (`owner_id` везде), но UI однопользовательский.

## Ключевые сценарии

1. Сбор книг из разрозненных источников в единый каталог (FB2/EPUB).
2. Отслеживание прогресса по циклам: прочитано/не прочитано, последняя книга цикла, следующая доступная.
3. Мониторинг источников (Author.Today, Litnet, OPDS, Flibusta) на новые публикации.
4. Нормализация FB2/EPUB (профиль `prose_compact`: только обложка, без внутренних иллюстраций, рабочее оглавление) без изменения литературного текста.
5. Доставка в FBReader через OPDS 1.2.
6. Быстрые мобильные действия (отметить прочитанной и т.д.), т.к. OPDS не возвращает позицию чтения.

## Ограничения

- Основная читалка — FBReader (Android), свой ридер не разрабатываем.
- Литературный текст книг неприкосновенен (инвариант, §7.1).
- Оригиналы файлов не удаляются и не изменяются.
- LLM — только классификатор/генератор proposal через OmniRoute, без права изменения файлов.
- Self-hosted на одном VPS, минимум инфраструктуры (PostgreSQL-backed очередь, без Redis/Celery/K8s).

## Non-goals

- Публичный сервис, соцсеть, магазин книг.
- Собственная читалка.
- Обход DRM/авторизации/CAPTCHA источников.
- Production-развёртывание (пока только документируется).

## Среда

- Разработка и тестовый контур — на целевой VPS (см. `DEPLOYMENT_STATE.md`).
- Соседние сервисы на той же машине: tracker (docker), OmniRoute, cypht — их нельзя ломать.
